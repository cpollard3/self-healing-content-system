How this was built with AI

I built Fidelis with Claude Code. Claude wrote the code, prompts, tests and docs. I acted as product owner and reviewer: I set the direction, decided what the system should be, and cut what was too complicated.

Understanding before building

Before any design, I had Claude walk through the brief and the decisions it implied, so I understood the problem before choosing a solution. I asked for a design document that was easy to follow, with diagrams.

Steering towards simplicity

The early designs were too elaborate, and I sent them back several times. I questioned the parts that weren't needed: an LLM treated as optional, mandatory manual review, layers of rule-based checks, and separate handling for every kind of documentation change. I reduced the core to one idea: for each fact in the knowledge graph, ask the LLM whether it is still true given the updated docs. That check became the centre of the design.

Shaping the pipeline

  • I asked for the knowledge graph as its own layer, with questions generated from the graph, so each question links to the facts it tests and healing can be targeted.
  • I set the order of the steps: choose the source of truth, propose questions, update the docs, check what changed and propose new questions.
  • I decided the split of work: the LLM proposes every update, and a person can optionally review it, seeing the old and new citation side by side.

A real proof of concept

I wanted the simplest MVP that genuinely works end to end with a real LLM, not a mock that only looks like it works. I also wanted an interface built for demoing, one that shows what happens at each step, including the exact prompts and responses.

Refining through use

I ran it live and reviewed the results. When I noticed that facts labelled as new were often things the old page already said, I had that fixed. I made sure the updated docs contain a genuinely new change, so the demo shows a real rewrite. I adjusted the demo's defaults and wording, and kept the docs in sync with what was built.

A final simplification pass

At the end I asked Claude to list everything that could be removed, and approved all of it. That included going live-only, merging the review step into the main flow, and dropping extra tracking the brief didn't need.

What Claude did

Claude wrote the implementation (Next.js, TypeScript, Vercel AI SDK, zod), the prompts and schemas, the tests and the docs, and debugged the LLM setup. I reviewed each stage and decided what to keep, change or remove.
