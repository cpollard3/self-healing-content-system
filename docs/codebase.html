Fidelis — codebase guide

One Next.js 16 app (about 3,000 lines of TypeScript). The UI and the pipeline live in the same app; there is no separate backend. Start with src/lib/steps.ts.

Map

Path What it holds
src/lib/steps.ts The 6 steps: prompts, zod schemas, applying LLM answers to the graph and questions, proposal checks, approve / reject / undo
src/lib/llm.ts callLlm(), the only code that talks to a model (OpenAI-compatible API via the Vercel AI SDK); pMap
src/lib/library.ts The documentation: original and updated text of each page; DEFAULT_SELECTION (Cloud Storage) and ALL_ORIGINAL
src/lib/types.ts Every data type, including the DB object
src/lib/text.ts Section parsing, page diff, quote verification (exact, or elided with "[...]" with every piece in order)
src/lib/store.ts JSON-file store (.data/db.json) with a write lock (mutate)
src/lib/stepMeta.ts Step titles and "what to notice" text, shared by server and UI
src/app/api/*/route.ts Thin routes: state, step, select, settings, reset, proposals/[id]
src/components/ The demo UI: App.tsx shell, StepViews.tsx panels, GraphView.tsx, Diff.tsx, QuestionView.tsx, LlmCalls.tsx, ui.tsx
scripts/run-all.ts Headless steps 1–6 against the real LLM, with a printed summary
tests/ Vitest: text helpers, callLlm with a mock model, the full pipeline with a scripted mock model

How one step runs

  1. App.tsx posts { n } to /api/step.
  2. The route runs mutate(db => runStep(db, n)). mutate serializes writers; runStep only accepts completed + 1.
  3. runStep sets db.running and calls the step function. LLM steps call callLlm with a zod schema, per page, up to LLM_CONCURRENCY at a time (default 1, for free tiers).
  4. Each LLM call is appended to db.llmCalls and written to disk; the browser polls /api/state, so calls appear live.
  5. The step applies the answers, sets completed, clears running. Errors land in db.error and show in the step.

Review actions and the review switch follow the same pattern: thin route, one mutate, logic in steps.ts.

The LLM layer

callLlm({ step, label, system, prompt, schema, log }):

  1. Calls generateText with Output.object({ schema }) against LLM_BASE_URL / LLM_MODEL (default Gemini gemini-3.1-flash-lite), with maxRetries: 8 so rate limits back off and retry.
  2. schema.parses the result; a malformed answer throws.
  3. Logs an LlmCall (prompt, response or error, model, ms) for the UI.

With no LLM_API_KEY it throws a message saying how to set one, and the header shows a red badge. Tests call setTestModel() with a mock model instead. Prompts live with their step in steps.ts.

Data model

All state is one DB object. The chain that makes healing targeted: question → fact ids → quote in a page.

Type Key fields
Concept name, kind, summary, examSection
Fact statement, quote, docId, conceptIds, status (current / changed / removed), origin (original / revised / new), replaces / replacedBy, quoteFound
FactCheck factId, verdict (still_true / changed / removed), reason, newFactId
DocChange title, oldTitle, status (unchanged / changed / new_page / removed_page), before, after
Question stem, 4 options, answer, explanation, factIds, status (live / hidden), history
Proposal kind (rewrite / new), before, after, reason, problems, status (pending / applied / rejected / undone)
LlmCall step, label, model, system, prompt, response, ms, error

db.snapshot copies concepts, facts and questions after step 3 so steps 2–3 can still show the "before" state.

Common changes

To Change
Add or edit a docs page LIBRARY in library.ts (## headings; null for a page that is new or removed)
Change the demo's starting selection DEFAULT_SELECTION in library.ts
Edit a prompt or schema The step function in steps.ts; update the scripted answers in tests/pipeline.test.ts if the schema changes
Use another model LLM_BASE_URL, LLM_MODEL, LLM_API_KEY in .env.local
Swap storage for a database readDb, writeDb, mutate in store.ts
Add a step Function in steps.ts, case in runStep, entry in STEP_META, panel in StepViews.tsx

Commands

npm run dev                  # http://localhost:3000
npm test                     # 16 tests, no key, no network
npm run run-all              # headless live run of the default selection; DOCS=all for every page, REVIEW=0 for review off
npm run typecheck
